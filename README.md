# 코트사이드 · 한전 본사 테니스

송변전·배전 각 4명의 친선 복식 대항전을 관리합니다. 기존 3·5경기 수동 오더 방식에 더해, 6경기를 3라운드·2코트로 진행하는 자동 대진 방식을 지원합니다.

## 지원 기능
- 일정, 시작 시간, 1~6번 코트, 사내 예약 승인 상태 안내
- 3·5경기: 팀 대표가 경기별 선수 2명을 정해 오더 제출·수정, 양 팀 제출 후 진행자가 확정
- 6경기: 팀별 남자 3명·여자 1명의 성별·직급으로 대진 자동 생성, 2개 코트와 라운드별 시간 지정 가능
- 참가자 이름·성별·직급 수정, 진행자는 양 팀을 관리하고 팀 대표는 자기 팀만 관리
- 수동 오더는 확정 전 상대 팀과 일반 관람자에게 비공개, 자동 대진은 공개
- 진행자만 최종 게임 스코어 입력·수정·초기화, 팀 승수 및 승리 팀 자동 계산
- 서버 저장, 다른 기기에서 조회, 30초 간격 갱신, 동시 수정 충돌 감지
- 결과 CSV 다운로드, 모바일 화면

## 대항전 진행 순서

### 3·5경기: 팀 대표가 오더 제출

1. 진행자가 일정, 경기 수, 코트와 안내문을 저장합니다.
2. 각 팀 대표가 자기 팀 참가자 4명과 경기별 복식 조를 입력하고 오더를 제출합니다.
3. 양 팀이 제출하면 진행자가 오더를 확정합니다. 확정 전에는 상대 팀 오더가 보이지 않습니다.
4. 진행자가 경기별 결과를 입력합니다. 3경기는 2승, 5경기는 3승을 먼저 거둔 팀이 대항전에서 승리합니다. 승리 팀이 정해진 뒤에도 남은 친선 경기 결과를 기록할 수 있습니다.

### 6경기: 3라운드·2코트 자동 대진

1. 진행자가 경기 방식을 6경기로 선택합니다. 사용할 코트 2개와 각 라운드 시작 시간은 선택 사항이며 나중에 입력할 수 있습니다.
2. 각 팀의 참가자 이름·성별·직급을 확인합니다. 팀마다 **1·2·3직급 남자 각 1명과 여자 1명**이 필요합니다. 1직급은 처장, 2직급은 부장, 3직급은 차장입니다. 진행자는 양 팀을, 팀 대표는 자기 팀을 수정할 수 있습니다.
3. 선수 구성이 맞으면 다음 대진을 자동으로 만듭니다. 선수 입력 순서를 바꿔도 남자 선수의 직급을 기준으로 같은 직급끼리 혼합복식을 치릅니다.

| 라운드 | 혼합복식 | 남자복식 |
| --- | --- | --- |
| 1라운드 | 양 팀 각각 1직급 남자 + 여자 | 양 팀 각각 2직급 남자 + 3직급 남자 |
| 2라운드 | 양 팀 각각 2직급 남자 + 여자 | 양 팀 각각 1직급 남자 + 3직급 남자 |
| 3라운드 | 양 팀 각각 3직급 남자 + 여자 | 양 팀 각각 1직급 남자 + 2직급 남자 |

각 라운드의 두 경기는 서로 다른 코트에서 진행합니다. 모든 선수는 총 3경기에 출전하며, 여자 선수는 혼합복식 3경기, 남자 선수는 혼합복식 1경기와 남자복식 2경기를 치릅니다. 여자 선수의 직급도 수정할 수 있으며 혼합복식 라운드는 남자 선수의 직급으로 정합니다.

6경기 방식에서는 별도의 오더 제출이나 진행자 확정 단계가 없습니다. 결과가 기록되기 전에는 명단을 수정해 대진을 갱신할 수 있습니다. 첫 결과가 기록된 뒤에는 명단을 바꾸기 전에 결과를 모두 초기화해야 합니다. 결과 입력·수정·초기화는 진행자만 할 수 있습니다.

6경기 결과를 모두 입력한 뒤 **경기 승수 → 전체 득게임 합계 → 최종 무승부** 순으로 대항전 결과를 판정합니다. 예를 들어 3승 3패이면 여섯 경기에서 얻은 게임 수를 합산하고, 그 합계도 같으면 무승부입니다. 모든 경기를 마치기 전에는 최종 승리 팀을 확정하지 않습니다.

### 기존 대회 데이터 유지

이전 버전의 3·5경기 대회는 이름·오더·제출 상태·확정 상태·결과를 그대로 유지합니다. 성별·직급 정보가 없는 기존 명단에는 사용자가 제공한 명단 순서에 맞춰 앞의 세 명을 남자 1·2·3직급, 마지막 한 명을 여자 3직급으로 초기 설정합니다. 참가자 정보는 화면에서 수정할 수 있습니다.

업데이트만으로 기존 대회를 6경기로 바꾸거나 저장된 오더를 다시 편성하지 않습니다. 진행자가 경기 방식을 바꾸면 기존 오더와 제출·확정 상태가 초기화되고, 6경기를 선택한 경우 자동 대진이 생성됩니다. 결과가 없는 대회는 오더가 확정돼 있어도 경기 방식을 바꿀 수 있습니다. 결과가 있는 대회는 결과를 모두 초기화한 뒤 변경해야 합니다.

## 실행
Node.js 22.13 이상과 npm이 필요합니다.

```sh
npm install
npm test
npm run typecheck
npm run build
npm run dev
```

Cloudflare D1의 DB 바인딩과 환경 변수 ADMIN_KEY가 필요합니다. INITIAL_ROSTER는 선택 항목이며 a, b 각각 4개 이름을 갖는 JSON 문자열입니다. 실제 참가자 정보와 관리 키는 소스에 포함하지 않습니다. 개발용 변수는 Git에서 제외되는 .dev.vars에 설정합니다.

로컬 D1에는 최초 한 번 drizzle/0000_young_talos.sql을 적용합니다. npm run build 이후 다음 명령을 실행합니다.

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_young_talos.sql
```

## 운영과 권한
일반 URL은 열람용입니다. 진행자 링크는 /#key=ADMIN_KEY 형식입니다. 진행자 화면에서 팀 대표 링크를 복사할 수 있습니다. 대표 키는 서버에서 HMAC으로 파생되며 상대 팀 변경이나 결과 입력을 허용하지 않습니다. 링크 소지자는 해당 권한을 가지므로 각 담당자에게만 전달합니다. ADMIN_KEY를 교체하고 재배포하면 이전 관리 링크가 모두 무효화됩니다. 참가자 이름·일정·확정된 수동 오더 또는 자동 대진·결과는 공개 링크에서 열람할 수 있습니다.

공개 범위는 사이트 호스팅의 접근 설정에서 관리하며, 이후 비공개로 전환할 수 있습니다. 비공개 전환은 열람 가능한 사람을 제한하는 설정입니다. 진행자·팀 대표의 입력 권한은 각각의 관리 링크로 구분합니다.

데이터는 단일 대회 레코드로 저장합니다. 날짜를 바꿔도 별도 대회가 생기지 않습니다. 여러 대회 이력, 개인 랭킹, 사내 예약 시스템 연동, 자동 메시지 발송은 이번 버전에 포함되지 않습니다. 관리 키를 분실하면 운영 환경 변수에서 새 키를 설정하고 재배포합니다.

스코어는 한 경기의 최종 게임 수이며 0~99의 정수, 경기별 동점은 허용하지 않습니다. 세트별 상세 기록·기권 처리는 지원하지 않습니다. 노애드·타이브레이크 등 세부 규칙은 진행자가 안내문에 작성합니다. 6경기 방식에서는 최종 팀 승수가 같을 때 전체 득게임 합계를 비교하므로 모든 경기의 스코어를 정확히 기록해야 합니다.

## 검증
npm test는 역할별 권한, 중복 선수, 수동 오더 확정, 자동 대진과 선수별 출전 횟수, 기존 데이터 보존, 스코어 수정 및 초기화, 경기 수 변경, 승리 팀 판정을 검증합니다. GitHub Actions는 테스트, 타입 검사, 빌드를 실행합니다.

GitHub 소스에는 초기 업로드 검토 용량 제한으로 package-lock.json이 포함되지 않습니다. 검증한 잠금 파일은 배포 버전별 소스 ZIP에 보존합니다.
